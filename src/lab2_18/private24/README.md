# Лабораторна робота 2.17. 

---

## Про файли

* **`ExchangeRateItem.kt`** - модель даних для однієї валюти. Зберігає назву валюти, курс НБУ та готівковий курс купівлі/продажу ПриватБанку (використовується `Double?`, оскільки для деяких валют банківський курс відсутній).
* **`ExchangeArchiveResponse.kt`** - коренева модель відповіді API. Містить дату запиту та масив елементів `exchangeRate`.
* **`PrivatBankApi.kt`** - Retrofit-інтерфейс, у якому описано `GET`-запит `exchange_rates?json` із параметром дати `@Query("date")`.
* **`PrivatBankNetworkModule.kt`** - налаштовує клієнт Retrofit із адресою `https://api.privatbank.ua/p24api/` та `GsonConverterFactory`.
* **`ExchangeArchiveUiState.kt`** - `sealed interface` для опису станів екрана: початковий (`Initial`), завантаження (`Loading`), успіх (`Success`) та помилка (`Error`).
* **`ExchangeArchiveViewModel.kt`** - керує логікою додатку. Перевіряє введену дату на коректність, виконує асинхронний запит через `call.enqueue()`, обробляє відповіді/помилки, оновлює `StateFlow` та скасовує незавершені запити при закритті.
* **`ExchangeArchiveScreen.kt`** - верстка екрана на Jetpack Compose. Містить поле вводу дати, `DatePickerDialog` (календар), кнопку завантаження та список курсів.
* **`MainActivity.kt`** - головна Activity, яка встановлює контент екрана у тему додатку `ComposeTheme`.

## Відповіді на контрольні запитання

**1. Чому для архівного API недостатньо моделі `List<CurrencyItem>` із прикладу поточних курсів?**
Запит поточних курсів повертає масив прямо в корені JSON, а архівне API повертає один великий об'єкт, всередині якого є поле `date` та масив `exchangeRate`. Якщо використати просто список, Gson не зможе розпарсити обгортку й виникне помилка. Тому потрібна окрема коренева модель для всієї відповіді.

**2. Чому відсутнє поле `purchaseRate` не варто замінювати нулем або значенням `purchaseRateNB`?**
Якщо поставити нуль, людина подумає, що банк віддає валюту безкоштовно. Курс НБУ це офіційний курс держави, за яким ПриватБанк купувати гроші у людей не зобов'язаний. Щоб не плутати й не дурити користувача, краще чесно показати пропуск "-", якщо у банку немає свого курсу.

**3. Як ViewModel допомагає зберегти дату, список та незавершений запит під час повороту екрана?**
Екран додатку при повороті повністю перестворюється, а ViewModel у цей момент продовжує спокійно працювати в пам'яті. Вона просто зберігає в собі завантажений список і стан запиту, тому новий екран одразу бере вже готові дані й не витрачає час на повторне завантаження з інтернету.

**4. Чому мережевий запит не потрібно повторювати при кожній рекомпозиції?**
Рекомпозиція в Compose це автоматичне перемалювання інтерфейсу, яке може ставатися десятки разів на секунду. Якщо робити запит при кожній рекомпозиції, додаток просто заспамить сервер тисячами однакових прохань, почне сильно зависати. Запит має запускатися тільки тоді, коли користувач сам натиснув кнопку.
