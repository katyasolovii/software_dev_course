# Лабораторна робота 2.18.

## Структура файлів проєкту

* **`MainActivity.kt`** - головна точка входу в додаток. Ініціалізує Compose-інтерфейс, вмикає відступи `enableEdgeToEdge()` та викликає головний екран `ExchangeRatesScreen`.
* **`MainApplication.kt`** - клас додатка (спадкоємець `Application`). Використовується для глобальної ініціалізації та реєстрації періодичного фонового завдання WorkManager під час старту застосунку.
* **`ExchangeArchiveScreen.kt`** - UI-шар на Jetpack Compose. Відображає поле вводу дати, кнопку оновлення, індикатор завантаження та список курсів валют у `LazyColumn` із захистом від перекриття елементами системи (`safeDrawingPadding`).
* **`ExchangeArchiveViewModel.kt`** - сполучна ланка між UI та даними. Зберігає стан обраної дати, підписується на зміни в базі Room через Flow та керує запуском фонових завдань через WorkManager.
* **`ExchangeRatesSyncWorker.kt`** - фоновий `CoroutineWorker`. Отримує дату, виконує мережевий запит через Retrofit до API ПриватБанку та зберігає отримані курси в локальну базу даних Room.
* **`ExchangeDatabase.kt`** - головний клас бази даних Room (Singleton). Створює та надає доступ до локальної БД SQLite.
* **`ExchangeRateDao.kt`** - інтерфейс з DAO-методами для Room. Зберігає курси валют (`insertRates`) та надає реактивний `Flow` для спостереження за курсами за конкретною датою (`observeRates`).
* **`ExchangeRateEntity.kt`** -таблиця Room (`exchange_rates`). Визначає структуру збереження даних із складеним первинним ключем `[date, currency]`.
* **`PrivatBankApi.kt`** - інтерфейс Retrofit для виконання HTTP-запитів до архівного API ПриватБанку за вказаною датою.
* **`PrivatBankNetworkModule.kt`** - модуль-одинак (Singleton), який налаштовує та створює готовий екземпляр Retrofit для роботи з мережею.
* **`ExchangeArchiveResponse.kt` та `ExchangeRateItem.kt`** - Data-класи для парсингу JSON-відповіді від сервера ПриватБанку за допомогою бібліотеки Gson.

## Контрольні запитання

### 1. Навіщо екран читає список лише з Room, хоча Worker уже отримав його з API?
Це основа паттерну Single Source of Truth, екран бере дані лише з одного місця. Worker просто завантажує курси з мережі та зберігає їх у базу, а Room одразу сповіщає екран про оновлення. Завдяки цьому додаток завжди показує дані з бази і стабільно працює навіть без інтернету.

### 2. Чому первинний ключ має містити і дату, і код валюти?
Курс однієї і тієї ж валюти змінюється щодня, тому сам по собі код валюти чи дата не є унікальними. Тільки пара "дата + валюта" утворює унікальний запис у базі. Це дозволяє зберігати історію курсів за різні дні та оновлювати існуючі записи без дублювання.

### 3. Чому періодичний Worker визначає поточну дату під час виконання, а не під час реєстрації завдання?
Періодична задача реєструється один раз при запуску додатка і працює днями чи тижнями. Якщо зафіксувати дату під час реєстрації, вона постійно качатиме той самий день. А визначаючи дату всередині `doWork()`, Worker кожного нового дня буде автоматично запитувати саме свіжу поточну дату.

### 4. Чим відрізняються відсутність збережених курсів, очікування мережі та помилка синхронізації?
Відсутність курсів означає, що база Room порожня для вказаного дня. Очікування мережі це процес, коли WorkManager чекає на інтернет або прямо зараз качає дані у фоні. Помилка синхронізації виникає при збої запиту, але при цьому вже раніше збережені в Room дані нікуди не зникають і залишаються на екрані.

### 5. Чому недостатньо запустити `enqueue()` усередині `doWork()` та одразу повернути `Result.success()`?
Виклик `enqueue()` виконується асинхронно у фоні, тому повернення `Result.success()` одразу ж завершить роботу Worker ще до того, як відповідь дійсно прийде з мережі. Використання `suspend`-функцій дозволяє чекати на реальне завантаження та збереження даних у базу, і лише після цього коректно завершувати завдання.

### 6. Що відбувається з Worker, ViewModel та підпискою на Room під час повороту екрана?
Worker продовжує спокійно працювати у системі Android незалежно від екрана. ViewModel не знищується і зберігає поточний стан дати. Підписка на Room на мить переривається під час перестворення екрана і одразу відновлюється, миттєво виводячи ті ж самі дані без повторних запитів.
